**RK3588 的 PCIe Host 驱动在 [kernel/drivers/pci/controller/dwc/pcie-dw-rockchip.c](/home/lubancat/LubanCat_SDK/kernel/drivers/pci/controller/dwc/pcie-dw-rockchip.c)。**

你看的 `pcie-rockchip-host.c` 是另一套控制器驱动，它的 [设备匹配表](/home/lubancat/LubanCat_SDK/kernel/drivers/pci/controller/pcie-rockchip-host.c:1296) 只有：

```c
.compatible = "rockchip,rk3399-pcie"
```

RK3588 使用 **Synopsys DesignWare PCIe 控制器**，因此放在 `dwc/` 目录下。可以从设备树一路对应到驱动：

1. [rk3588.dtsi](/home/lubancat/LubanCat_SDK/kernel/arch/arm64/boot/dts/rockchip/rk3588.dtsi:518) 中，`pcie3x4` 等节点声明：
   ```dts
   compatible = "rockchip,rk3588-pcie", "snps,dw-pcie";
   ```

2. [pcie-dw-rockchip.c 的匹配表](/home/lubancat/LubanCat_SDK/kernel/drivers/pci/controller/dwc/pcie-dw-rockchip.c:1588) 对应：
   ```c
   .compatible = "rockchip,rk3588-pcie",
   .data = &rk_pcie_rc_of_data,
   ```
   这里的 **RC（Root Complex）就是 Host 模式**。

这份驱动由多个 Rockchip SoC 共用，所以函数大多叫 `rk_pcie_*`，没有单独命名成 `rk3588_*`。建议按下面顺序阅读：

| 入口 | 作用 |
|---|---|
| [rk_pcie_probe()](/home/lubancat/LubanCat_SDK/kernel/drivers/pci/controller/dwc/pcie-dw-rockchip.c:2179) | 驱动入口；当前配置开启了线程初始化 |
| [rk_pcie_really_probe()](/home/lubancat/LubanCat_SDK/kernel/drivers/pci/controller/dwc/pcie-dw-rockchip.c:1929) | 实际初始化，按 RC/EP 模式分支 |
| [rk_add_pcie_port()](/home/lubancat/LubanCat_SDK/kernel/drivers/pci/controller/dwc/pcie-dw-rockchip.c:1145) | 设置 Host 回调，调用 DesignWare 公共初始化 |
| [rk_pcie_host_init()](/home/lubancat/LubanCat_SDK/kernel/drivers/pci/controller/dwc/pcie-dw-rockchip.c:1122) | 配置 Root Complex，建立链路 |
| [rk_pcie_establish_link()](/home/lubancat/LubanCat_SDK/kernel/drivers/pci/controller/dwc/pcie-dw-rockchip.c:754) | PCIe 链路训练 |

公共 Host 逻辑在 [pcie-designware-host.c](/home/lubancat/LubanCat_SDK/kernel/drivers/pci/controller/dwc/pcie-designware-host.c:293)，包含调用上述 Host 回调及 `pci_host_probe()` 枚举下游设备。对应编译选项是 **`CONFIG_PCIE_DW_ROCKCHIP`**，你的 `kernel/.config` 中已经启用。

## 2026-10-22 16:54:47 · 助手

在这份 SDK 中，**RK3588 PCIe 控制器的寄存器地址写在设备树的 `reg`，访问下游设备的地址窗口写在 `ranges`；两者的解析路径不同。** 另外，`Region 0` 可能指设备的 BAR0，也可能指 iATU Region 0，下面分别对应。

**1. 控制器寄存器地址：设备树 `reg` → `rk_pcie_resource_get()`**

以 PCIe 3.0 ×4 控制器为例，在 [rk3588.dtsi 的 pcie3x4 节点](/home/lubancat/LubanCat_SDK/kernel/arch/arm64/boot/dts/rockchip/rk3588.dtsi:518)：

```dts
reg = <0x0 0xfe150000 0x0 0x10000>,
      <0xa 0x40000000 0x0 0x400000>;
reg-names = "pcie-apb", "pcie-dbi";
```

每组是 `<地址高32位 地址低32位 长度高32位 长度低32位>`，因此：

| 名称 | CPU 物理基地址 | 大小 | 用途 |
|---|---:|---:|---|
| `pcie-apb` | `0xfe150000` | 64 KiB | Rockchip 控制器的控制、状态寄存器 |
| `pcie-dbi` | `0xa40000000` | 4 MiB | DesignWare DBI 寄存器空间，包含 RC 自身配置空间 |

注意第二个地址是 **`0xa40000000`**，要把高 32 位一起计算。

驱动在 [pcie-dw-rockchip.c 的 rk_pcie_resource_get()](/home/lubancat/LubanCat_SDK/kernel/drivers/pci/controller/dwc/pcie-dw-rockchip.c:1246) 获取并映射它们：

```c
dbi_base = platform_get_resource_byname(pdev, IORESOURCE_MEM,
                                       "pcie-dbi");
rk_pcie->dbi_base = devm_ioremap_resource(&pdev->dev, dbi_base);
rk_pcie->pci->dbi_base = rk_pcie->dbi_base;

apb_base = platform_get_resource_byname(pdev, IORESOURCE_MEM,
                                       "pcie-apb");
rk_pcie->apb_base = devm_ioremap_resource(&pdev->dev, apb_base);
```

这里驱动拿到的已经是 `struct resource`。**真正把 `reg`、`reg-names` 解析成资源的是 OF 核心：**

```text
of_device_alloc()                     drivers/of/platform.c
  → of_address_to_resource()         drivers/of/address.c
      → 解析 reg、reg-names，填充 platform_device 的资源

rk_pcie_really_probe()
  → rk_pcie_resource_get()
      → 按名字获取资源
      → devm_ioremap_resource() 映射成内核虚拟地址
```

对应源码：[of_device_alloc()](/home/lubancat/LubanCat_SDK/kernel/drivers/of/platform.c:107)、[of_address_to_resource()](/home/lubancat/LubanCat_SDK/kernel/drivers/of/address.c:866)。

**2. 下游 PCIe 地址窗口：设备树 `ranges` → PCI 核心 → DesignWare 驱动**

同一个 `pcie3x4` 节点中：

```dts
ranges = <0x00000800 0x0 0xf0000000 0x0 0xf0000000 0x0 0x100000
          0x81000000 0x0 0xf0100000 0x0 0xf0100000 0x0 0x100000
          0x82000000 0x0 0xf0200000 0x0 0xf0200000 0x0 0xe00000
          0xc3000000 0x9 0x00000000 0x9 0x00000000 0x0 0x40000000>;
```

每一行结构为：

```text
<PCI空间类型 PCI地址高位 PCI地址低位 CPU地址高位 CPU地址低位 大小高位 大小低位>
```

在这个节点中，PCI 地址和 CPU 地址数值相同：

| 窗口 | CPU 物理起始地址 | 大小 |
|---|---:|---:|
| 下游配置空间访问窗口 | `0xf0000000` | 1 MiB |
| I/O 窗口 | `0xf0100000` | 1 MiB |
| 32 位非预取内存窗口 | `0xf0200000` | 14 MiB |
| 64 位可预取内存窗口 | `0x900000000` | 1 GiB |

解析调用链是：

```text
dw_pcie_host_init()
  → devm_pci_alloc_host_bridge()
    → devm_of_pci_bridge_init()
      → pci_parse_request_of_pci_ranges()
        → devm_of_pci_get_host_bridge_resources()
          → of_pci_range_parser_init()
```

解析结果放进 `bridge->windows`。具体看：

- [drivers/pci/of.c](/home/lubancat/LubanCat_SDK/kernel/drivers/pci/of.c:259)：解析 `ranges`。
- [dw_pcie_host_init()](/home/lubancat/LubanCat_SDK/kernel/drivers/pci/controller/dwc/pcie-designware-host.c:293)：读取窗口，设置 `pp->cfg0_base` 等字段。
- [dw_pcie_setup_rc() 内的窗口设置](/home/lubancat/LubanCat_SDK/kernel/drivers/pci/controller/dwc/pcie-designware-host.c:586)：根据内存、I/O 窗口配置 outbound iATU。

**3. 如果你说的是 `lspci -vv` 中的 `Region 0`**

例如：

```text
Region 0: Memory at ...
```

这是**被枚举 PCIe 设备的 BAR0**。一般没有单独的设备树属性指定它的最终地址，而是：

```text
设备配置空间中的 BAR0
  → PCI 核心探测 BAR 类型和大小
  → 从 Host 的 ranges 内存窗口中分配地址
  → 写回 BAR0
  → 下游设备驱动通过 pci_resource_start(pdev, 0) 获取地址
```

BAR 探测看 [pci_read_bases()](/home/lubancat/LubanCat_SDK/kernel/drivers/pci/probe.c:321)，枚举与资源分配入口看 [pci_host_probe()](/home/lubancat/LubanCat_SDK/kernel/drivers/pci/probe.c:3005)。

**4. 如果你说的是 iATU 的 Region 0**

它是地址转换单元的第 0 个窗口。在这份 Host 驱动中，[dw_pcie_other_conf_map_bus()](/home/lubancat/LubanCat_SDK/kernel/drivers/pci/controller/dwc/pcie-designware-host.c:441) 使用它访问下游配置空间：

```c
dw_pcie_prog_outbound_atu(pci, 0, type,
                         pp->cfg0_base, busdev, pp->cfg0_size);
```

其中 `0` 就是 Region 0，`pp->cfg0_base` 来自上述 `ranges` 的配置空间窗口。**它与设备 BAR0 是两个不同概念。**
